# Geek Season — backend

Сервер сайта для подготовки к ЕГЭ по информатике.
Сейчас умеет: показывать номера ЕГЭ (страница «Задания»), список задач-прототипов
номера (с фильтром и сортировкой), проверять ответ ученика и пускать на сайт
через Telegram-бота (QR-код или 6-значный код).
Данные хранятся в PostgreSQL, временные коды входа — в Redis.

## Перед первым запуском: бот и .env

1. В Telegram напиши @BotFather → `/newbot` → придумай имя. Он выдаст **токен**.
2. Скопируй `.env.example` в `.env` и заполни:
   - `BOT_TOKEN` — токен от BotFather;
   - `BOT_USERNAME` — имя бота **без @**, например `GeekSeasonBot`;
   - `JWT_SECRET` — длинная случайная строка:
     `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

Файл `.env` в Git не попадает. Токен бота никому не показывай: с ним можно управлять ботом.

## Запуск — одна команда (Docker)

Нужен только установленный Docker.

```bash
docker compose up --build
```

Открой <http://localhost:8000/docs> — там можно нажимать на запросы и смотреть ответы.
Остановка: `Ctrl+C`. Удалить вместе с данными базы: `docker compose down -v`.

Поднимутся четыре контейнера: база `db`, `redis`, сервер `api` и `bot`.
При старте `api` сам:
1. создаёт таблицы в базе (миграции Alembic);
2. заполняет номера ЕГЭ и несколько примеров задач (`app/seed.py`);
3. запускается.

## Запуск без Docker (для разработки в PyCharm)

Базу удобно оставить в Docker, а сервер запускать у себя — так работает `--reload`
(сервер перезапускается при сохранении файла).

```bash
docker compose up -d db redis                 # только база и Redis
python -m venv .venv
# Windows:  .\.venv\Scripts\activate     Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                          # Windows: copy .env.example .env
alembic upgrade head                          # создать таблицы
python -m app.seed                            # заполнить данными
uvicorn app.main:app --reload
```

Бот — отдельная программа. Запусти её во **второй** вкладке терминала:

```bash
python -m app.bot
```

## Что попробовать в /docs

| Запрос | Что покажет |
|---|---|
| `GET /numbers` | 25 карточек номеров (1…27, номера 19–21 объединены) и сколько в каждом задач |
| `GET /numbers/17/tasks` | Задачи номера 17 — без ответов |
| `GET /numbers/7/tasks?source=demo` | Только задачи из демоверсии |
| `GET /numbers/1/tasks?sort=easy` | Сначала лёгкие (`new`, `old`, `easy`, `hard`) |
| `POST /tasks/8/check` с `{"answer": "2 20"}` | `is_correct: true` |
| `POST /tasks` | Добавить задачу (ответ `201` и её `id`) |
| `PATCH /tasks/{id}` | Изменить только присланные поля |
| `DELETE /tasks/{id}` | Убрать задачу в архив (`204`) |
| `POST /auth/telegram/start` | Ключ и ссылка на бота для QR-кода |
| `GET /auth/telegram/status/{ключ}` | `pending` → после «Да» в боте `confirmed` и токен |
| `POST /auth/code` с `{"code": "123456"}` | Вход по коду из бота (`/login`) |
| `GET /me/stats` | Статистика ученика для профиля (нужен токен) |
| `GET /auth/me` | Кто я — нужен заголовок `Authorization: Bearer <токен>` (в /docs — кнопка **Authorize**) |

Коды ответов: `200`/`201`/`204` — всё хорошо; `404` — такого нет; `422` — неправильные
данные в запросе. Неверный ответ ученика — это тоже `200`, а результат в поле `is_correct`.

## Как устроен код

```
app/
├── main.py                 собирает приложение из модулей
├── seed.py                 начальные данные: номера ЕГЭ и примеры задач
├── core/
│   ├── config.py           настройки и секреты из .env
│   ├── db.py               подключение к PostgreSQL
│   └── redis.py            подключение к Redis
├── bot/                    Telegram-бот (python -m app.bot)
│   ├── __main__.py         запуск
│   └── handlers.py         ответы на /start, /login и кнопки «Да/Нет»
├── modules/auth/           модуль «вход»
│   ├── models.py           ТАБЛИЦА users
│   ├── service.py          QR-ключи и коды в Redis, создание пользователя
│   ├── tokens.py           JWT — «пропуск» после входа
│   ├── deps.py             get_current_user — «кто делает запрос»
│   └── router.py           адреса /auth/...
├── modules/progress/       модуль «прогресс»
│   ├── models.py           ТАБЛИЦА attempts — каждый ответ вошедшего ученика
│   ├── service.py          статистика: решено, точность, серия, дни, по номерам
│   └── router.py           GET /me/stats
└── modules/tasks/          модуль «банк заданий»
    ├── models.py           ТАБЛИЦЫ базы: ExamNumber (номер), Task (задача)
    ├── schemas.py          что API принимает и отдаёт
    ├── service.py          логика: запросы к базе, проверка
    ├── answers.py          сравнение ответов (числа, слова, «2 20»)
    └── router.py           адреса API → вызов сервиса → код ответа
alembic/versions/           миграции — история изменений таблиц
tests/                      автотесты
```

Путь запроса `POST /tasks/8/check`:
`router.py` проверяет JSON по схеме из `schemas.py` → `service.get_task` достаёт
задачу из базы → `answers.py` сравнивает ответы → JSON уходит обратно.

### Как считается прогресс

Если ученик вошёл, каждый `POST /tasks/{id}/check` сохраняет строку в `attempts`.
Задача **решена** — была хотя бы одна верная попытка; **не решена** — попытки были,
но все неверные. Архивные задачи в «решено» не входят. Дни (серия, график)
считаются по часовому поясу `TIMEZONE` (по умолчанию Europe/Moscow).
Вошедший ученик также получает `solved` в `GET /numbers` и `status` у задач
в `GET /numbers/{code}/tasks`.

### Как сравниваются ответы

Ответ режется по пробелам, части сравниваются по очереди:
числа — как числа (`4` = `4.0`, `0,25` = `0.25`), остальное — как текст без учёта
регистра (`ZYXW` = `zyxw`). Поэтому подходят ответы-числа, ответы-буквы (№2)
и ответы из двух чисел (№17, 18, 26, 27).

## Если меняешь таблицы

Модель в `models.py` сама таблицу в базе не меняет. После правки модели:

```bash
alembic revision --autogenerate -m "что изменилось"   # создаст файл миграции
# открой созданный файл в alembic/versions и проверь его глазами
alembic upgrade head                                 # применить
```

Новый файл `models.py` из другого модуля нужно импортировать в `alembic/env.py`.

### Как работает вход через Telegram

```
Сайт: POST /auth/telegram/start → ключ (в Redis на 5 минут, статус pending)
      показывает QR со ссылкой t.me/<бот>?start=<ключ>
Бот:  /start <ключ> → «Войти?» [Да] [Нет]
      «Да» → создаёт/находит пользователя по telegram_id, ключ → confirmed:<id>
Сайт: каждые 2 с GET /auth/telegram/status/<ключ>
      confirmed → выдаёт JWT, ключ удаляется (одноразовый)
```

Вход по коду: `/login` в боте → 6 цифр в Redis на 5 минут → `POST /auth/code`.
Новый `/login` отменяет прежний код. Больше 5 попыток в минуту с одного адреса — `429`.

Защита от подставного QR: бот не входит молча, а спрашивает «Да / Нет» и предупреждает
не подтверждать чужие QR-коды.

## Тесты

Тесты используют отдельную базу `geek_test` (в Docker она создаётся автоматически)
и перед каждым тестом очищают её. Redis в тестах ненастоящий (fakeredis),
а нажатие «Да» в боте тест делает вызовом той же функции, что и бот.

```bash
docker compose up -d db
pytest
```
